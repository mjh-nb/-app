

### **项目计划书：岐黄 AI —— 基于多模态大模型的中医健康智能体**

#### **一、 项目概述**

**1.1 项目背景与痛点 (Background)**
在现代生活节奏加快、健康意识提升的背景下，中医药“治未病”和整体调理的智慧正焕发新的吸引力。然而，想获得一次专业、便捷的中医咨询却并不容易。一方面，资深中医师资源稀缺且集中，挂号难、路途远、成本高，将许多仅是处于亚健康状态、需要日常调理的年轻人挡在门外。另一方面，市场上能找到的中医类应用，大多只是将古籍和文章数字化，变成了静态的百科查阅工具，用户面对自身复杂的症状感到困惑，却无法获得具有交互性和针对性的指导。

更令人担忧的是技术尝试带来的新问题。当前，直接使用强大的通用人工智能进行问诊初看很便利，实则隐藏着巨大风险。这些模型固有的“幻觉”现象，在医疗领域可能导致其凭空编造病症或给出有害建议，这种不可靠性使得它们难以被严肃应用。同时，即便一个 AI 给出了结论，其思考过程也如同一个无法打开的“黑箱”，既无法向用户解释“为何如此”，也难以让专业人士进行审核，完全违背了医学严谨、可验证的根本要求。此外，纯粹的文字交流也剥离了中医“望闻问切”的精华，特别是缺失了“舌诊”这一直观重要的环节，使得判断如同盲人摸象，不够全面。

因此，我们正处在一个矛盾的关口：市场渴望获得便捷、智能的中医健康服务，但现有的技术路径要么过于死板，要么过于冒险，无法在专业性、安全性与体验感之间找到平衡。这正是“岐黄 AI”希望解决的核心问题。

**1.2 项目目的与立意 (Purpose)**
面对上述困境，本项目的初衷并非是要创造一个能替代医生的“万能 AI”，而是希望借助“软件无处不在”的现代思维，将中医辨证论治的核心逻辑，封装进每个人触手可及的智能手机里。我们致力于打造一位“口袋里的老中医”——它不是一个天马行空的聊天伴侣，而是一个严谨、稳定、可解释的健康顾问。其核心建设目标，是构建一个深度融合中医诊断学思想与现代人工智能技术的交互系统。这个系统能够模拟中医“四诊合参”的流程，通过与用户自然的交流和多模态信息的采集，进行初步的健康状态辨识与调理指导，为公众提供一个可信赖、可触及的日常健康管理起点，让中医的智慧以更安全、更亲切的方式融入现代生活。

**1.3 创新点 (Innovation Points)**

*   **架构创新：双引擎驱动（Dual-Engine）—“规则引擎 + LLM”的双脑协同模式**
    在技术选型初期，我们发现市面上大多数“AI 医生”存在一个致命缺陷：大模型（LLM）是基于概率生成的，它会产生“幻觉”。比如用户仅仅说了一句“头痛”，大模型可能会因为检索到高血压的语料而直接做出误导性诊断。在医疗健康领域，这种“概率性的不确定”是不可接受的红线。
    因此，我们没有盲目追求“全 AI 化”，而是独创了一套 **“左脑逻辑 + 右脑表达”** 的双引擎架构：
    *   **逻辑层（左脑 - 规则引擎）：** 这是系统的“定海神针”。我们构建了一套基于 Excel 的结构化中医知识图谱，将模糊的症状映射为可量化的数值。诊断过程不再是黑盒的“猜谜”，而是严谨的数学计算（如：命中核心症状+10 分，命中舌象特征+5 分）。这一步确保了诊断结果 **100% 可控、可解释、无幻觉**。
    *   **表达层（右脑 - LLM）：** 这是系统的“嘴巴”。大模型不负责下诊断，只负责“翻译”。它获取规则引擎计算出的确切结论（如“脾虚湿蕴”），结合预置的现代医学译文，将其转化为用户听得懂、有温度的自然语言建议。

*   **技术创新：基于视觉大模型（VLM）的语义级舌象分析**
    *   **内容：** 不同于传统依赖大量标注数据训练的 CNN 识别，本项目创新性引入 **通义千问-VL (Qwen-VL)** 视觉大模型。通过构建 **“闭集约束提示词 (Closed-set Constrained Prompting)”**，强制大模型在预设的中医术语库（如“淡白舌”、“齿痕”）中进行特征匹配。这种方法不仅解决了传统小模型泛化能力差、抗光线干扰弱的问题，更实现了从“像素分类”到“语义理解”的跨越，精准模拟中医专家的“望诊”思维。

*   **体验创新：多模态自然交互**
    *   **内容：** 融合“文本对话”与“图像采集”，模拟真实中医“望闻问切”全流程。本系统突破了传统健康应用"填表式"的僵硬交互，创造性地实现了"像和老中医聊天一样"的自然问诊体验。
    *   **1.多模态信息融合：** 用户既可以用文字描述症状（如"我最近总是头晕"），也可以直接拍摄舌苔照片上传。系统支持舌像独立采集，用户点击对应按钮即可选择拍照或从相册选取，操作简单直观。前端会将图片自动压缩至合理尺寸（800×800，JPEG 质量 80%），确保上传速度快且不占用过多流量。
    *   **2.智能发送控制：** 发送按钮采用"三选一"激活逻辑——只要用户输入了文字、上传了舌像或上传了面像中的任意一项，发送按钮就会亮起，避免空请求。这种设计既保证了交互效率，又防止了误操作。
    *   **3.长期记忆管理：** 系统会自动保存每次问诊的关键信息（如"舌苔偏白"、"饭后困倦"），形成用户的健康档案。当用户再次打开应用时，无需重复输入既往病史，AI 会基于历史记忆进行更精准的判断。
    *   **4. 合规安全设计：** 在应用首页底部和结果页均明确标注"本系统仅用于中医文化学习与健康管理参考，不构成医疗诊断或治疗建议"，避免法律风险。我们从不给出具体药名或处方，只提供调养方向（如"作息建议：早睡早起"），确保合规性。

#### **二、 技术方案**

**2.1 总体架构 (Overall Architecture)**
*   **架构图描述：** 采用经典的 B/S 分离架构。
    *   **客户端 (Client)：** Android 原生开发（Java + XML 布局），遵循经典的分层架构设计，负责数据采集与展示。
        *   UI 层：8 个核心 Activity 串联完整流程 (Splash -> Main -> Profile -> Chat ...)。
    *   **网络层：** 基于 OkHttp 4.12.0 的异步请求封装。
    *   **存储层：** 基于 SharedPreferences 的本地持久化（SavedContext）。
    *   **服务端 (Server)：** 基于 **FastAPI** 的高性能异步框架。
    *   **数据层：** **“反常识”的无数据库设计**。直接采用 Excel + Pandas 的内存计算方案。
        *   **热插拔的知识库：** 医疗规则相对静态，Excel 存储实现了“业务逻辑与代码的物理分离”，非技术人员可直接维护规则。
        *   **内存级响应速度：** 启动时全量加载至内存构建索引，查询速度远快于数据库 IO。
        *   **零运维成本：** 部署极简，Python 环境即插即用。

*   **实现原理：** (原稿内容...结构化信息的精准提取...强类型的多轮对话状态管理...完全可解释的自研加权匹配算法...)

**2.2.2 舌象视觉识别模块**
*   **技术关键词：** Vision-Language Model (VLM)、Zero-shot Learning (零样本学习)、Prompt Engineering (提示词工程)、Base64 Encoding。
*   **实现原理：**
    本模块利用了当前最先进的多模态大模型技术，替代了传统的 CNN 训练模式，实现了更高的鲁棒性和通用性。
    1.  **图像预处理与编码：**
        后端接收到移动端上传的图片流后，首先进行格式校验与去噪处理。随后，利用 `tempfile` 机制生成临时文件，并将其转换为标准的 Base64 编码，确保能被 VLM API 高效读取。
    2.  **构建“专家级”视觉提示词 (Visual Prompting)：**
        这是本模块的核心。普通的识图只会返回“这是一张舌头”，而我们需要的是中医维度的特征。我们设计了一套复杂的 System Prompt：
        *   **角色设定：** “你是一位经验丰富的中医AI助手”。
        *   **闭集约束 (Closed-set Constraints)：** 我们将标准中医教材中的舌象分类（如“舌淡红、舌红、舌绛”和“苔白、苔黄、苔腻”）硬编码到 Prompt 中，强制要求模型**“只能从给定候选项中选择”**，严禁模型使用“可能”、“大概”等模糊词汇或自造词。
        *   **思维链引导 (CoT)：** 要求模型先描述整体画面（如光线、角度），再聚焦局部特征，最后输出结论，提高推理准确度。
    3.  **结构化输出解析：**
        要求大模型严格返回 JSON 格式数据（包含 `tongue_substance`, `tongue_coating` 字段）。后端接收后，通过 Python 的 `json` 库进行解析和清洗，将非结构化的视觉信息转化为系统可计算的“特征代码”（如 `PaleRed`），无缝传递给后续的规则引擎。

#### **三、 项目计划**

**3.1 可行性分析 (Feasibility)**
*   **技术可行性：** 团队已完成 FastAPI 后端与 Android 前端的 MVP（最小可行性产品）联调。核心算法（规则匹配）已通过 Python 单元测试，逻辑闭环。
*   **数据可行性：**
    不同于需要从零收集万张图片的传统训练模式，本项目基于预训练的通用视觉大模型（Qwen-VL）。该模型已在海量数据上拥有了强大的泛化能力。我们只需通过少量的典型舌象图片（约 50 张）进行 **API 接口测试与 Prompt 微调**，即可达到极高的识别可用性，大大降低了数据门槛和开发风险。

**3.2 实施规划 (Implementation Roadmap)**

本项目遵循标准的敏捷软件开发（Agile Development）流程，通过持续迭代，确保产品的高质量交付。

*   **第一阶段（第1-3天）：需求分析与原型设计 (Requirement & Prototyping)**
    *   任务：明确“亚健康人群”的核心需求，梳理中医问诊的业务逻辑。
    *   产出：业务流程图 (Flowchart)、UI 高保真原型 (Figma/墨刀)、API 接口文档 (OpenAPI Specification)。

*   **第二阶段（第4-8天）：核心模块开发 (Core Development)**
    *   **后端开发：** 搭建 FastAPI 框架，完成 rules.xlsx 和 diseases.xlsx 知识库的结构化导入。编写并调优 VLM 视觉提示词，实现高精度的舌象特征提取。
    *   **前端开发：** 搭建 Android 原生框架，封装网络请求库，实现多模态（图文）聊天界面的流畅交互。

*   **第三阶段（第9-12天）：系统集成与联调 (Integration & Testing)**
    *   任务：打通“端-云”数据链路，验证“拍照 -> 识别 -> 规则匹配 -> 诊断生成”的全链路闭环。重点测试在弱网环境下的图片上传稳定性及大模型响应延迟优化。
    *   产出：集成测试报告、功能完备的 Beta 版 APK。

*   **第四阶段（第13-15）：体验优化与交付 (Optimization & Delivery)**
    *   任务：进行 UI/UX 细节打磨，增加加载动画与错误提示，提升用户体验。编写合规性免责声明，录制项目演示视频，整理最终交付文档。

#### **四、 未来展望与改进方向 (Future Outlook)**

本项目的 Beta 版仅是“岐黄 AI”生态的第一步。我们规划在未来的版本迭代中，引入更多前沿硬件与数据技术，构建一个全感知、全场景的中医健康闭环。

**4.1 引入智能穿戴硬件，补全“切诊”拼图**
*   **背景：** 目前系统已实现“望”（舌/面诊）、“问”（对话）、“闻”（待开发语音音色分析），唯独缺少“切”（脉诊）。
*   **规划：** 后续版本将适配支持 **PPG（光电容积脉搏波）** 或 **压力传感器** 的智能手环/手表（如 OPPO Watch 等赛题指定设备）。通过蓝牙实时获取用户的心率变异性 (HRV) 和脉搏波形数据，利用深度学习模型分析脉象（如滑脉、弦脉），真正实现“四诊合参”，大幅提升体质辨识的准确度。

**4.2 拓展智能家居场景，打造“魔镜”健康管家**
*   **规划：** 将视觉识别算法嵌入**智能化妆镜**或洗漱台屏幕。用户每天早晨刷牙洗脸时，镜子自动采集当天的面色与舌象，生成连续的健康趋势报告（Trend Analysis）。从“主动问诊”变为“无感监测”，让健康管理融入生活点滴。

**4.3 构建“中医数据银行”，赋能科研与传承**
*   **规划：** 在用户授权的前提下，对采集到的海量舌象、问诊对话进行脱敏处理，构建**“现代人群亚健康中医语料库”**。这些高质量的结构化数据可反哺给中医药高校与科研机构，用于训练垂直领域的中医大模型（TCM-LLM），助力中医经验的数字化传承与现代化验证。
